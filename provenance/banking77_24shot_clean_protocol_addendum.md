# Addendum to the pre-registered clean protocol (amendments A1–A3)

**Status: pre-registration.** This addendum amends `banking77_24shot_clean_protocol.md` (commit 8455e7e). It is
committed before any model is run under the protocol. Where it conflicts with the protocol, the addendum wins.
Nothing has been scored on the selection split or the test set.

## A1. No truncation

- **The risk.** The library's default tokenisation right-truncates at 2,048 tokens. Qwen3's tokenizer truncates
  on the right, so an over-long prompt would silently lose the query and the answer slot.
- **How close we are.** Measured on 300 train queries: description prompts reach 1,935 tokens, 113 short of the
  limit.
- **Amendment (replaces "Max length 2,048" in §3).**
  - Reader prompts are never truncated.
  - The run uses `truncate=False` with a hard bound of **4,096** tokens. Any prompt longer than that raises an
    error before the forward pass, so a truncated row is impossible rather than merely unlikely.
- **Reporting.** The untruncated token-length distribution (mean, median, p95, max, count over the bound) is
  recorded for exactly the prompts the reader is given:
  - the selection split, both option texts × 7 orders, in `selection_scores.json`;
  - the test run, selected text × its orders, in the meta.
- **Shared code path.** Prompt construction is shared between inference and length measurement
  (`RetrievalEnsemble._prompts_for_order`), so the lengths reported are those of the prompts actually scored.
- **The repo default is unchanged.** It keeps the library default (right-truncation at 2,048). Its R2 dump
  will record whether any of its prompts exceeded 2,048.

## A2. Secondary analyses (declared now, none affect selection)

**Primary.** Exact two-sided McNemar of the selected configuration against the public reproduction's per-item
predictions (`results/predictions.csv` @ 5cac4ff). Rows are joined by test index, with the truth label checked
on every row.

**Secondary.** These are computed on the test run of the selected configuration only:

| analysis | definition |
|---|---|
| Accuracy, 95% bootstrap CI | 10,000 resamples of test rows with replacement, seed 20261007, percentile interval. |
| Wilson 95% interval | Reported as well, for direct comparison with the reproduction, which reports Wilson. |
| Macro-F1 | The reproduction's definition: mean over classes of 2·tp / (actual + predicted). |
| Log loss | Clipped at 1e-15, as the reproduction does. |
| Brier | Summed over classes, as the reproduction does. |
| ECE | Ten equal-width bins [i/10, (i+1)/10) on max-probability confidence, the last bin closed at 1. This is the reproduction's `ece_10_bins` definition. |

- **Distribution used.** Log loss, Brier and ECE are computed on the **final-temperature ensemble
  distribution** (the final temperature is fitted on the selection split). They are also reported on the
  uncalibrated combined distribution.
- **Comparison with the reproduction.** Our values are reported next to the reproduction's own reported Jev
  values from `results/results.json` @ 5cac4ff (accuracy, Wilson interval, macro-F1, log loss, Brier, ECE),
  read at run time.
- **Comparison with the repo default.** An exact McNemar of the selected configuration against the repo default
  (the R2-default dump, run after the clean test run). This comparison is descriptive only.

## A3. Provenance of the "descriptions" option text

- **The candidate's text.** It is exactly `examples/banking77_descriptions.py`: 77 one-line phrases.
- **Same text as the study used.** It matches the study's description set word for word (77 of 77 labels, same
  label order). The study used no other per-class description set for Banking77.
- **How it was authored.** It was written once, in a single commit on 2026-09-22 (20:51 +08:00), and has never
  been edited since. The commit describes the text as hand-authored, that is, written directly rather than
  generated by a script.
  - **What it is based on.** The actual Hugging Face label names. It was written to separate near-duplicate
    intents (for example `card_arrival` vs `card_delivery_estimate`, and the `top_up_*` and `verify_*_identity`
    families).
  - **Who wrote it.** The commit is recorded under the owner's account. The study was carried out by LLM
    coding-agent sessions, so the text was most likely written by such a session. Which model and version is
    **not recorded**.
- **What may have been seen first.**
  - Banking77 **full-test zero-shot accuracies already existed** when the descriptions were written. They had
    been computed with bare label names.
  - No per-class test confusion analysis appears in the record before the commit.
  - Whether the authoring session looked at individual test errors is **unknown**.
  - Nothing indicates any edit after Banking77 test outputs: there has never been an edit at all.
- **Decision.** The set stays a candidate, with this disclosure.

## Other changes adopted

- **Zero-shot member in fp32.** The NLI part of the zero-shot member (M3) runs in **fp32**, matching the
  published zero-shot dumps.
- **Train split only during selection.** Only the train split is loaded until the selection result is written.
  The test split, with its labels, is loaded only in the test phase.
- **Balanced folds.** Folds are stratified and dealt round-robin starting at fold (class index mod 5). This gives
  each class 2–3 rows per fold and fold sizes of 184–186. The fold seed stays 20261006.
