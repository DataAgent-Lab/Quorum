[UNDERSTANDING]

Two external zero-shot methods beat Quorum's default on the label-rich / description-sensitive sets:
- **PIE** (arXiv:2305.14827): a bi-encoder PRE-TRAINED to be intent-aware (utterance↔intent-name contrastive
  pretraining on other intent data). Root cause of its edge: TASK SPECIALISATION of the encoder.
- **dataless** (arXiv:2407.17862): bge-large + per-class natural-language DESCRIPTIONS, cosine-matched. Root
  cause: RICHER LABEL TEXT (descriptions) vs bare names.

Quorum's default uses GENERAL-purpose members and LABEL NAMES only — so trailing these on CLINC150 (0.652 vs
PIE 0.831 / dataless 0.815) and SNIPS (0.853 vs 0.9257) is expected.

Two principles to learn in:
  (P1) DESCRIPTIONS as a first-class label text. Quorum's `ZeroShotEnsemble.predict_proba(..., label_texts=)`
       ALREADY accepts arbitrary label text — so descriptions need no new code, just: enable/document them as a
       first-class path, ship example descriptions, and MEASURE the gain (does it close the CLINC/SNIPS gap?).
  (P2) An INTENT-SPECIALISED encoder as an ensemble member (PIE-style), if a suitable open model exists.

Plan: validate P1 cheaply first (SNIPS descriptions vs names, full test), then spec P2. Proceeding.

[RESULT | T3 — P2 measured, NEGATIVE]

Searched for an open intent-specialised encoder:
  - PIE (arXiv:2305.14827, amazon-science/intent-aware-encoder, Apache-2.0): NO pretrained weights released
    (training code only; repo archived 2024-08). Using it => pre-train our own encoder = out of scope.
  - dataless's encoder = bge-large = a member we already have; its edge is descriptions (P1), not the encoder.
  - Only usable open English dialogue/intent-specialised ST checkpoint: sergioburdisso/dialog2flow-joint-bert-base
    (EMNLP'24, MIT).

Added Dialog2Flow as a 4th ensemble member, measured on SNIPS names (full 1400):
  3-member = 0.8529   +Dialog2Flow(4) = 0.8350   delta = -0.0179
  McNemar 4-vs-3: b=20 c=45 p=0.0026 -> the 3-member is SIGNIFICANTLY better -> Dialog2Flow HURTS.
Root cause (as predicted up front, not post-hoc): D2F optimises utterance<->dialogue-action similarity, not
utterance<->intent-NAME matching, so cosine-to-label-text is a noisy member.

Verdict: no usable open intent-specialised encoder improves the ensemble; PIE-style specialisation is
inaccessible without training an encoder ourselves (out of scope). AC-3 satisfied as a measured negative.
